# Prompt Forge PRD 摘要

## 1. 产品定位

Prompt Forge 是面向知识工作者、开发者和内容创作者的桌面提示词优化工具。它解决的不是“替用户润色一句话”，而是通过有目的的多轮访谈，把隐含目标、背景、受众、约束和交付标准显式化。

核心价值：

1. 降低高质量提示词的撰写门槛。
2. 让 AI 的追问有理由、可理解、可追溯。
3. 把对话过程沉淀为可复用的本地资产。
4. 保持模型服务可选、API Key 可控、数据本地优先。

## 2. 用户与场景

目标用户：

- 需要构建研究、写作或分析提示词的研究生与知识工作者
- 需要把产品需求转成代码生成提示词的程序员
- 需要统一品牌表达的营销与内容团队

场景模板：

| 模板 | 重点澄清内容 | 输出侧重 |
| --- | --- | --- |
| 通用优化 | 不预设专业领域，澄清目标、背景、受众、约束与成功标准 | 通用、准确、可执行 |
| 学术写作 | 研究问题、领域、证据标准、引用规范、目标读者 | 论证严谨性、可核验性、声称边界 |
| 代码生成 | 技术栈、运行环境、输入输出、安全与验收标准 | 可运行实现、异常处理、测试与假设 |
| 文案创作 | 品牌、受众、渠道、语气、卖点、行动目标 | 结构、语气样例、输出规格、禁用表达 |
| 图像生成 | 主体、用途、平台、视觉风格、构图、光照、配色、画幅、文字及授权风险 | 可直接用于图像模型的完整视觉提示词 |
| 自定义场景 | 由用户填写名称、说明、AI 关注点和输入示例 | 按用户定义的领域重点追问与生成 |

「图像生成」复用现有 `TemplateDefinition` 的 `id / name / shortName /
description / focus / accent / example` 字段，与内置及自定义场景完全兼容，
无需改变历史记录结构。

## 3. 核心流程

```text
选择场景
  ↓
输入原始提示词
  ↓
点击“开始分析”
  ↓
AI 判断信息是否充分
  ├─ 充分 → 生成结构化专业提示词 → 本地保存
  └─ 不足 → 返回 1–5 个问题及 WHY → 用户回答
                              ↓
                      AI 再次判断
                      ├─ 仍不足 → 下一轮（硬上限 5 轮）
                      └─ 充分 → 自动生成
  ↓
复制 / 重新生成 / 历史回看
```

每次模型调用只完成一个明确决策：继续澄清或直接生成。达到 5 轮后强制生成，避免无限追问。

## 4. 功能范围

### 必须项

- 原始提示词输入与场景切换
- 通用模式与自定义场景的新建、编辑、删除
- AI 信息缺口分析
- 每轮 1–5 个澄清问题
- 每个问题展示具体提问理由
- 当前轮次与回答进度
- 多轮问答与自动完成判定
- 模块化专业提示词生成
- 一键复制与重新生成
- 本地历史、详情恢复、删除、清空、JSON 导出
- 多模型服务配置与连接测试
- API Key 系统凭据库存储
- 自定义背景色、文字色、强调色与基础字号
- 外观设置实时预览、恢复默认、保存和重启恢复
- 项目上下文：目标、风格、角色、历史对话、素材
- 项目与生成历史关联，删除项目不删除历史
- 变量模板一键复制为可直接使用的纯文本提示词
- 变量模板采用有序章节结构，支持章节重命名、增删和排序
- 变量模板提供原始占位符版与已填值版两种可复制提示词
- 变量模板支持独立 JSON 导入与导出
- 项目历史交互可按项目筛选、勾选、摘要并作为新提示词上下文
- 项目交互摘要支持模型生成、本地缓存、Token 预算与截断提示
- 新生成历史保存来源记录 ID，可在结果与导出数据中追溯
- 可从一条或多条项目交互提炼变量模板，并展示来源映射
- 主题/角色变量的笛卡尔积组合、实例预览及批量输出
- 知名 IP、品牌和真实人物的非阻断合规提醒
- 日常对话回复助手：消息上下文、发送者身份、背景追问与多语气回复
- 主动发起沟通：从简单目的补全角色、背景、语气和输出格式
- 前置背景注入与生成后的多轮修改闭环
- 上下文附件：支持 PNG、JPG、WEBP、TXT、MD、PDF、DOCX
- 附件支持点击选择、拖拽、粘贴图片、缩略图预览、大小提示与删除
- 图片在视觉模型中通过 `image_url` 随请求发送；不支持图片的模型会明确阻断
- PDF 与 DOCX 在本地提取文本，并以带边界的参考上下文发送给模型
- 附件内容随提示词历史保存，历史恢复时按需读取
- “完成后保留附件”开关持久化，默认保留以便继续修改

### 非目标

- 用户账号、云同步、团队协作
- 在线提示词市场
- 强制数据库加密
- 首版内自动比较多个模型的输出版本

## 5. UI 布局

| 区域 | 内容 | 主要操作 |
| --- | --- | --- |
| 顶栏 | 品牌、全局命令入口、模型状态与快捷操作 | 命令面板、主题切换、新建和设置 |
| 左侧栏 | “场景 / 项目 / 历史”三段导航 | 切换/管理场景、项目和历史 |
| 中部工作区 | 原始输入、进度、历史问答、当前问题组 | 开始分析、回答本轮、提交 |
| 附件区 | 文件缩略图/图标、名称、大小、隐私提示 | 选择、拖拽、粘贴、删除附件 |
| 右侧结果区 | 最终提示词、复制、重新生成、指标 | 复制结果、强制重生成 |
| 设置弹窗 | 服务类型、Base URL、模型、Key、连接测试 | 保存、测试、删除已有 Key |
| 外观设置 | 三项颜色选择器、Hex 输入、字号滑块与预览 | 实时预览、恢复默认、保存外观 |

视觉语言采用深色工作台、低饱和网格、等宽状态码和高亮绿/蓝状态色。所有主要流程在同一窗口完成。

## 6. 验收标准

1. 输入无效时不会发起模型请求。
2. 模型返回 1–5 个问题，界面逐题显示 WHY。
3. 回答后可继续追问，完成 5 轮后不再开启第 6 轮。
4. 完成态提示词包含任务所需的结构化模块，并自动保存。
5. 复制、重新生成、历史恢复、删除和导出可操作。
6. API Key 不出现在 SQLite、前端状态、日志或导出 JSON 中。
7. API 错误、网络错误和 Key 缺失均以可理解的中文提示呈现。
8. 不支持的附件格式或超限文件不会进入等待队列，并显示明确原因。
9. 当前模型不支持图片时，界面提示并阻止提交，不得静默忽略图片。
10. 文档文本和图片随历史保存，恢复历史时可以重新预览并继续修改。

## 7. 项目上下文

项目表单采集以下信息：

| 字段 | 用途 |
| --- | --- |
| 项目名称 | 项目选择、标题和模型上下文标识 |
| 项目目标 | 长期目标、受众与最终交付 |
| 风格 | 语气、视觉和叙事规范 |
| 角色 | 人物关系、性格、外观和称呼 |
| 历史对话 | 前情提要、已确认决策与连续性约束 |
| 素材 | 脚本、产品资料或其他事实来源 |

项目以独立记录保存在 SQLite 中，生成时作为 `project_context` 传入模型；
历史记录保存 `project_id`。删除项目不级联删除历史。

## 8. 变量模板

变量模板是独立于场景模板的可复用提示词库，由有序章节和变量定义组成：

- 章节：包含稳定 ID、名称、类型和正文，支持增删、改名与排序
- 变量：包含 key、显示名称、填写说明和参考默认值
- 默认章节：角色、任务、上下文、变量说明、规则、示例、输出格式、质量检查

模板新增、编辑后连同章节顺序持久化到 SQLite；内置模板只读，但可以复制为
自定义模板。用户既可以复制保留 `{{key}}` 占位符的原始模板，也可以在填写
变量后复制已替换完成的完整提示词。模板支持独立 JSON 文件导入和导出。
本模块不调用模型，不产生 Token 费用。

## 9. 日常对话回复助手

用户粘贴收到的消息并选择发送者身份。首轮必须由 AI 提出 1–5 个背景问题，
覆盖前情、关系边界、期望结果、时间压力和语气偏好。每轮问题均显示 WHY；
最多 5 轮后强制生成。

生成结果为 3–4 条直接可发送的话术，分别采用稳妥、自然或简短等不同策略。
每条回复独立显示策略说明和复制按钮。项目上下文可作为补充背景，且不会覆盖
回复助手的系统规则。

回复助手可切换为“主动发起沟通”：用户只输入目的或大白话，AI 首轮必须补问
发送者角色、任务背景、收件对象、语气和输出格式。结果同样提供多条发送内容。

提示词输入与回复输入均支持前置背景信息。生成结果下方提供继续修改输入框及
语气、长度快捷按钮；模型会收到上一版结果和修改意见，返回完整的新版本，用户
可反复迭代至满意。

## 10. 项目交互上下文与模板提炼

项目交互上下文将项目固定设定、本次输入/附件、历史交互摘要定义为独立来源。
用户可按项目查看历史，勾选记录并触发生成摘要。摘要必须由模型生成，聚焦澄清
约束、用户偏好、已确认决策和被否决方案；缓存键由来源 ID 集合与摘要版本组成，
来源更新时间变化时自动失效。

生成前显示预计 Token、预算、实际引用清单和截断数量。超限时按最近记录优先
保留可容纳的摘要，并明确提示未引用记录，用户可调整预算或取消勾选。新历史
保存实际引用的来源记录 ID。

在已选择并完成摘要的历史中，可触发“提炼为提示词模板”。模型输出角色、任务、
上下文、变量说明、规则、示例、输出格式和质量检查等有序章节，并给出每条来源
交互到章节或变量的映射。结果进入现有模板编辑器，用户确认后才写入自定义模板
库；模板 JSON 导出同时保留来源 ID 和映射。
